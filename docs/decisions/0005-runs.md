# 5. A run is a folder that describes itself

**Status:** Proposed

## Context

convy 0.1 wrote a run as `results/runs/<agent>/<start>.jsonl`: a header with the agent, its version,
the models' names and how many attempts were planned, then a line per attempt. The report read every
journal ever and grouped runs by agent and version. That left questions the data could not answer:

- whether two runs played the same scenarios — only ids and claims were kept, so an edited scenario
  mixed old and new attempts;
- whether a run finished — it was guessed from the count of lines, and a stopped run could not be
  continued;
- which claim failed — the judge gave one verdict for all of them.

Evaluation tools that keep runs answer these the same way. Inspect AI writes a log per eval with its
specification, status and samples, lists logs by reading their headers, and continues a stopped one
with `eval-retry <log>`. lm-evaluation-harness writes the resolved configuration and hashes of its
tasks next to the results. LangSmith ties an experiment to a version of its dataset. In all of them
the report is built from the runs and can be rebuilt; the runs are what is kept.

## Decision

- **A run is one execution of a set of scenarios against one build of one agent**, `k` attempts per
  scenario. `convy run a b` makes two runs.
- **A run is a folder,** `results/<agent>/<id>/`, the id being the start time and four random hex
  digits. `run.json` holds `{"format": 2, "spec": …, "status": …}` and is rewritten whole, through a
  temporary file; `attempts.jsonl` holds a line per attempt and is only appended to.
- **The specification is a snapshot:** every scenario as it was played, the agent's `version`, the
  models' names, `k`, `parallel`, `turn_timeout`, the convy version, and sha256 fingerprints of the
  agent's file and `models.py`. Whether two runs played the same scenario follows from a fingerprint
  of its text, computed from the snapshot.
- **The status is explicit:** `running`, then `finished` or `interrupted`. A run whose process died
  stays `running`; it is shown as not finished.
- **A run continues by its id and unchanged.** `convy resume <id>` takes no settings: it plays the
  missing attempts with the specification's scenarios and settings, and refuses when the agent's file,
  `models.py`, the version or a model's name differs.
- **The judge decides each claim,** and an agent that failed is `Failed`, not judged.

**Compatibility.** The run's folder is convy's only durable format. A reader understands the current
`format`. When the format changes next, older runs are either converted as they are read or refused
with a message that says so; which, is decided with that change. 0.1 journals are not read: convy says
so once and the agents are run again. The report and its view records are rebuilt from runs and carry
no version.

## Alternatives

- **One self-describing JSONL per run:** the specification on the first line, a status line at the
  end. One file to send, but the status cannot be rewritten in place, and resuming puts the end in
  the middle of the file.
- **SQLite,** as promptfoo keeps evals. Queries and growth are easy, but a run can no longer be read
  with a text editor, sent as a file or removed by deleting a folder.
- **Resume the latest unfinished run without an id.** Ambiguous with several agents or terminals, and
  it could take a run that is still being played by another process.
- **Keep the run's settings out of `resume`'s checks.** A continued run would then mix two agents in one
  set of numbers.

## Consequences

- The report can say whether a run is better than the one before, on the scenarios both played
  unchanged, and which claim failed.
- A run is self-contained: it can be read, sent or deleted on its own.
- `resume` cannot see a change in a module the agent imports, or in the service behind it.
- `RunJournal.play` plays the `Bench` it is given; nothing checks that it matches the run's
  specification, so a Python caller can write a `run.json` that does not describe what ran (the
  command always builds the bench from the spec it records).
- 0.1 results must be produced again.
